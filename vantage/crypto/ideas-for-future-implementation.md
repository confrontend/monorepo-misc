- 2026-08-24 — idea: there is currently no reliable in-memory client-side store for API-fetched data with real invalidation. Confirmed by review: the shared `api()` fetch helper (ui/main.tsx) is a bare fetch wrapper with no caching or dedup; the dominant pattern (77 `useState` + 27 `useEffect` fetch-effect pairs) unconditionally re-fetches on every relevant effect trigger (e.g. every Scrutiny-tab revisit); the one TanStack Query usage (wallet-detail trade history) is deliberately configured with `staleTime: 0` and `retry: false` to reproduce the old always-refetch behavior exactly, not to cache; Zustand's `rosterStore.ts` holds only UI selection state, not fetched data; localStorage is scoped to UI preferences only (a deliberate choice after a browser-side data cache masked a stale server-cache bug earlier this session). The only thing making repeat fetches cheap today is the server's own disk-backed cache (`copytrade_report_cache` in SQLite), a different layer with its own documented fragility. Most natural next step: extend the existing TanStack Query pattern with real `queryKey`/`staleTime` invalidation tied to the actions that actually change server data (roster sync, Dune fetch completion, GMGN refresh), rather than inventing a separate store. Not scoped or started.
